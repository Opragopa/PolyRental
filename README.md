# PolyRental

Telegram-бот, Mini App и сайт для бесплатной аренды оборудования медиацентра «Полимер».

Текущая версия — **0.5.6-hotfix-6**, схема БД — **20261105_43**. Номер приложения берётся из [VERSION](VERSION), показывается в профиле и `/health`, входит в URL статических ресурсов. Изменения: [CHANGELOG](CHANGELOG.md), [hotfix](docs/releases/v0.5.6-hotfix-6.md). Состояние, проверки и ограничения: [docs/current-state.md](docs/current-state.md).

## Возможности

- Клиент выбирает оборудование в каталоге, собирает корзину, задаёт даты и время по МСК и отправляет заявку. На компьютере время вводится с клавиатуры. Доступность проверяется после выбора периода и повторно на сервере при подтверждении.
- `pending` и `needs_changes` не резервируют оборудование. Подтверждённая заявка сохраняет резерв; конкретные экземпляры назначаются при подготовке. Аренда бесплатная, автоматические зависимые позиции и буфер после возврата отключены.
- Плановые выдача и приём: будни 09:00–20:00, летом 08:30–20:00 по Москве с календарными исключениями. Начало бронирования — с четвёртого календарного дня. Фактические действия сотрудников и подтверждения клиента доступны круглосуточно.
- После подтверждения клиент заполняет защищённую анкету. До подготовки он может запросить изменение с обязательной причиной. Пока сотрудник принимает решение, сроки, состав и резерв сохраняются, подготовка блокируется. Одобрение открывает исправление и повторное подтверждение; отказ оставляет заявку прежней.
- Сотрудники проверяют заявки, готовят, выдают и принимают технику. Цепочка: `pending → confirmed → preparing → ready → issued → return_inspection → returned`; сервер проверяет права, закрепление, проверки оборудования и действия клиента.
- Каталог поддерживает категории, фото моделей, экземпляры, комплектацию, особенности, ремонт, внешнюю занятость и атомарный CSV-импорт. Удаление артикула администратором сохраняет историю заявок.
- История показывает действия, время по МСК и публичные имена участников. Telegram ID остаются техническими идентификаторами. Причины запросов и приватные комментарии зашифрованы и не выводятся в общую историю.
- Есть поддержка, напоминания, SLA-эскалации, iCalendar-подписка и объявления обычных релизов в приложении и настроенном Telegram-канале. Hotfix использует объявление основного релиза.

## Настройка и запуск

Нужны Docker с Compose и отдельный Telegram-бот. Для работы пользователей нужен публичный HTTPS-адрес. Все параметры перечислены в [справочнике окружения](docs/configuration.md).

1. Скопируйте `.env.example` в `.env`. Заполните `BOT_TOKEN`, `BOT_USERNAME`, `ADMIN_IDS`, независимый список `PII_ADMIN_IDS`, разные случайные `SESSION_SECRET` и `ICAL_TOKEN`, `PII_MASTER_KEY`, реквизиты оператора и `PUBLIC_URL`.
2. `PII_MASTER_KEY` и `BACKUP_MASTER_KEY` — разные ключи из 32 случайных байт в base64url. Для каждого ключа отдельно выполните локально `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Ключ архива нужен для чтения сохранённых документов; его нельзя терять или заменять без миграции данных.
3. В BotFather задайте Main Mini App URL `PUBLIC_URL/miniapp` и домен входа на сайт. Production использует `https://polyrental.opragopa.com`. Compose передаёт `PUBLIC_URL` из `.env` боту и Mini App.
4. Соберите приложение, примените миграции и запустите сервисы:

```powershell
docker compose -f compose.yaml -f compose.miniapp.yaml build bot miniapp
docker compose -f compose.yaml -f compose.miniapp.yaml up -d db redis
docker compose -f compose.yaml -f compose.miniapp.yaml run --rm miniapp alembic upgrade head
docker compose -f compose.yaml -f compose.miniapp.yaml up -d bot miniapp
```

Mini App слушает `127.0.0.1:8000`. Проверка готовности — `/health`, Mini App — `/miniapp`, сайт с входом через Telegram — `/site`. Для уведомлений пользователь должен начать диалог с ботом. Сессия сайта действует 24 часа.

```powershell
docker compose -f compose.yaml -f compose.miniapp.yaml logs -f miniapp bot
```

`http://localhost:8000/miniapp?preview=1` показывает демонстрацию без отправки заявок. Для реальной Mini App нужны Telegram и HTTPS. Старая административная панель `app.web` в этом режиме не запускается; резервный вариант — `docker compose up -d --build db web bot`. Одновременно занимать порт 8000 обоими режимами нельзя. Для управляемого облака предусмотрен `compose.cloud.yaml` с CA прокси при сборке.

## Production и обновление

Публичный адрес — `https://polyrental.opragopa.com`; HTTPS обслуживает Windows Nginx в `C:\nginx-1.31.8`. Приложение доступно Nginx по `127.0.0.1:8000`. Старый домен сохранён для ранее отправленных ссылок. Сертификат, Nginx и откат описаны в [инструкции переезда](docs/domain-migration-opragopa.md).

При обновлении применяйте миграции до перезапуска бота и Mini App. `scripts/deploy.ps1` проверяет точный SHA, выполняет `git pull --ff-only`, сборку, миграции и проверку `/health`. Он использует `compose.yaml` и `compose.miniapp.yaml`; Windows Nginx и сертификаты им не меняются. `compose.public.yaml`, `scripts/enable-https.ps1` и `scripts/renew-certificate.ps1` относятся к прежнему контейнерному Nginx.

GitHub Actions проверяет каждый push в `main` и pull request. Автодеплой требует self-hosted Windows runner с меткой `PolyRental`, GitHub Actions **Secret** `DEPLOY_PATH` и **Variable** `DEPLOY_ENABLED=true`. При выключенном флаге deployment пропускается. Эти настройки не относятся к `.env` приложения. Последний проверенный запуск: [CI для 74d07fc](https://github.com/Opragopa/PolyRental/actions/runs/42092454238); автодеплой в нём пропущен.

## Роли и документы

`ADMIN_IDS` задаёт список сотрудников; подроли `operator`, `manager`, `admin` хранятся в БД и назначаются в настройках сотрудников. `PII_ADMIN_IDS` независимо разрешает полные ПД и проверку анкеты. ID только из PII-списка не получает складских полномочий. Пустой/некорректный `ADMIN_IDS` и некорректный непустой `PII_ADMIN_IDS` останавливают запуск.

Оператор и выше подтверждает и отменяет заявки, готовит, выдаёт и принимает технику, решает запрос клиента на изменения, скрывает артикулы и управляет пустыми пользовательскими категориями. В Mini App создание/редактирование моделей и экземпляров, фото, CSV, предложение новых сроков/состава и передача заявки требуют менеджера или администратора. Удаление артикула и управление ролями — только администратор. Поддержка требует служебную подроль и PII-доступ. Подробности: [матрица ролей](docs/design/roles.md), [различия старых интерфейсов](docs/design/roles-as-is-2026-11-05.md).

Новые расписки — DOCX по существующему шаблону; исторические PDF сохраняются. При выдаче документ включается в неизменяемый пятилетний архив. Клиент получает только свою расписку, полные документы сотрудника — только PII-администраторы. Отдельный доверенный подписант и отметка бумажной подписи не являются обязательным серверным условием выдачи/завершения. Логическое подтверждение не заменяет бумажную подпись.

Фото и реквизиты шифруются AES-256-GCM. `DOCUMENT_CHECK_MODE=local` включает предварительную локальную проверку Pillow/Tesseract (`rus+eng` в Docker); решение принимает PII-администратор. `manual` оставляет только ручную проверку. Без ключа и заполненных реквизитов оператора сбор анкеты не включается. `DADATA_API_KEY` включает серверные подсказки адресов; без него адрес вводится вручную.

## Каталог и хранение

Создайте модель, затем её экземпляры. Полное название хранится в `name`; `kind`, `brand`, `key_spec` — отдельные характеристики. Серийные номера не возвращаются клиентским API. CSV-шаблон скачивается из «Импорт и настройка комплектов → Добавить оборудование из CSV»: UTF-8, разделитель `;` или `,`, до 1 МБ и 500 экземпляров. Поддерживаются технический шаблон и опись; пустой/`-` серийный номер не создаёт значение, повторные серийные номера допустимы, инвентарный код уникален. Ошибка отменяет весь импорт.

Redis хранит кэш публичных данных без ПД и сохранения на диск. Compose ограничивает память 128 МБ и не публикует порт. Доступность кэшируется до 5 секунд, категории и календарь — до 5 минут; изменения меняют ревизию PostgreSQL в той же транзакции. Без Redis приложение читает БД напрямую.

`scripts/backup_encrypted.py` шифрует поток `pg_dump` без промежуточного открытого дампа; по умолчанию хранит копии 30 дней. Скрипт запускается на хосте и получает `BACKUP_MASTER_KEY` из окружения процесса, сам `.env` не читает. Сроки хранения, мониторинг и восстановление: [стратегия хранения](docs/storage-and-retention.md), [настройки](docs/configuration.md).
