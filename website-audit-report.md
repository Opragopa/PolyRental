# PolyRental — Website Audit и проверка приложения

> Дата: 25 октября 2026, время — МСК
> Аудитор: Codex, навык website-audit
> Среда исправлений: локальный код и Docker с отдельной БД `polyrental_test`
> Интерфейс: `http://localhost:8001/qa/customer`, `/qa/admin`, `/qa/pii`; временный QA сервер остановлен после проверки
> Действующая сборка: `http://localhost:8000/miniapp`; публичный HTTPS в этом проходе повторно не проверялся
> Итог: **43 passed**, 1 предупреждение зависимости; исходный набор содержал 11 тестов

## Executive Summary

Предыдущий отчёт проверял преимущественно клиентский preview и не покрывал большую часть ролевого рабочего процесса. Расширенная проверка обнаружила ошибки доступности, комплектации, документов, повторных запросов и мобильных служебных экранов. Исправления внесены в код; девять первоначальных регрессионных сценариев сначала воспроизвели ошибки, затем прошли после исправления. Результат относится к тестовой сборке: действующие контейнеры Mini App и бота в рамках аудита не пересобирались.

Контекст продукта взят из README, ROADMAP, исходного кода и прежнего отчёта: русскоязычная Telegram Mini App для клиентов рентала, сотрудников склада и отдельной роли проверки документов. Проверялись бронирование, история, согласие и анкета, каталог, комплектация, осмотры, выдача, возврат, ремонт, iCal, резервный сценарий бота и старая веб-панель. Это проверка перечисленных сценариев, а не гарантия отсутствия любых ошибок во всех возможных состояниях.

- 🟡 IMPORTANT: тексты о безвозмездной передаче в документах расходятся с представлением почасовой стоимости в интерфейсе. Нужно определить, является ли ставка оплатой аренды или справочной оценкой, и согласовать тексты продукта. Бизнес-модель предположением не менялась.

- Проверена серверная подпись/срок Telegram initData, отсутствие серийных номеров в клиентском API, чужие заявки, разделение ADMIN_IDS/PII_ADMIN_IDS.
- Все административные API маршруты автоматически проверены с отсутствующей авторизацией и ролью клиента: соответственно 401 и 403.
- Существующие проверки покрывают шифрование анкеты, загрузку изображений, удаление метаданных, сроки хранения, формирование документов, базовый полный цикл аренды с дефектом при возврате и буфером.

### Браузер

- Клиент: будущие даты → пустой выбор с ошибкой → выбор техники → контакты → сводка → создание заявки → новая заявка с пустыми датами.
- Согласие: переход без отметки блокируется.
- Сотрудник: открытие комплектации → выбор другого экземпляра → сохранение → блокировка готовности без осмотра → успешный осмотр → готовность.
- Оператор: три синтетические фотографии, последовательная навигация, отключение кнопок на границах, закрытие.
- Каталог: открытие редактора, создание тестового артикула, появление сохранённой карточки.
- Мобильные области 320/390/430 px создавались iframe, то есть реально меняли viewport для CSS; это не тест на физических телефонах.
- Измерения проверенных состояний: 320 px → clientWidth/scrollWidth 305/305; 390 px → 375/375; 430 px → 415/415. Разница обусловлена вертикальной полосой прокрутки; список выходящих за границы элементов пуст.
- Снимки: [комплектация 320 px](docs/qa/mobile-assignment-320.png), [просмотр документа 390 px](docs/qa/mobile-document-390.png). Белое изображение документа намеренно синтетическое; реальные паспортные данные не использовались.

| URL | Результат |

Отсутствие `/login` ожидаемо для режима miniapp-only: старая панель запускается отдельным сервисом web. Поэтому прежняя общая оценка этих четырёх 404 как единого критического сбоя была неточной. Публичные политика и условия остаются незавершённой частью публикации; в репозитории есть только проект политики с незаполненными реквизитами. Проект не публиковался как утверждённый документ. Отсутствие robots.txt само по себе не блокирует оформление заявки.

## Ограничения проверки

- Реальный запуск внутри Telegram, нативные MainButton/BackButton, получение уведомлений и загрузка фотографий с физических телефонов остаются для приёмки на реальных устройствах. Для ролевого браузерного QA использовались подписанные тестовые пользователи и отдельный тестовый токен.
- Уведомления в тестах и временном QA сервере заменены локальными заглушками; фактические сообщения людям не отправлялись.
- Нагрузочное тестирование, восстановление резервной копии, аудит инфраструктуры и юридическое утверждение документов не выполнялись.
- Действующие сервисы и рабочая БД не изменялись. Для проверки исправлений на рабочем адресе нужна новая сборка Mini App и бота.
- Скрипт `scripts/qa_server.py` отказывается запускаться вне БД с именем `polyrental_test`; его нельзя включать в production. Перед автотестами QA сервер нужно остановить, поскольку тестовая фикстура очищает эту же тестовую БД.
