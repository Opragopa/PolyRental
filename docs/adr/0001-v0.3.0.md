# ADR: обновление v0.3.0

Статус: принято, 26 октября 2026.

## Календарь и совместимость

RangeCalendar — отдельный локальный JS-компонент без зависимостей и сетевых вызовов. Календарные дни представлены строками ISO, арифметика идёт в UTC; время аренды всегда сериализуется с `+03:00`. UI показывает МСК, неделю с понедельника и даты с русскими названиями месяцев. Выбор завершается двумя тапами, включая аренду в один день с разным временем; третий тап начинает новый диапазон. Сброс сохраняет времена для повторного выбора. Черновик диапазона и техники остаётся в прежнем localStorage-формате.

Сохранён бизнес-дефолт текущего репозитория: выдача с даты «сегодня по Москве + 4 дня». Требование запретить прошлые дни выполняется вместе с этим более строгим правилом. Буфер не является минимальным сроком аренды: это пауза между бронированиями одного артикула. Сервер повторно проверяет доступность с буфером при создании заявки. Не меняем существующий wire-формат `start`/`end`, несмотря на формулировку задания `starts_at`/`ends_at`: последние остаются полями ответа.

Сетка всегда содержит шесть недель и резервирует высоту 326 px до загрузки JS. На мобильном первом шаге скрыта вступительная промо-шапка, основной action закреплён внизу либо используется Telegram MainButton. Быстрые сроки и пояснение буфера доступны в раскрываемом блоке. Не добавляем общий список «занятых дней» (ФТ-12): оборудование выбирается после периода, а занятость зависит от артикула, количества и времени; глобальная блокировка дня была бы неверной.

Фото и заглушки каталога — 4:3, `object-fit: cover`, операторская миниатюра занимает 76×57 px. Место под изображение резервируется независимо от исходного разрешения.

## Роли

Единственный источник списков — env `ADMIN_IDS`, `PII_ADMIN_IDS`; разбор и функция `role_for` общие для бота, API и web. Telegram ID должен быть подтверждён сообщением бота, подписанным initData или проверенным Telegram Login с серверной сессией. Клиентский `initDataUnsafe` используется только для удобства заполнения контакта, не для разрешений.

`ADMIN_IDS` обязателен, значения — положительные десятичные ID в диапазоне BIGINT, через запятую. Пробелы и повторы допустимы; пустой элемент и неверное значение отклоняют весь список. `PII_ADMIN_IDS` может быть пустым, но непустой список также валидируется целиком. PII-администратор получает служебные права; обычный администратор не получает PII-права. Отдельная роль/список операторов не вводится: `ADMIN_IDS` обслуживает существующую операторскую роль.

Reply-клавиатура предлагает подписанный inline-запуск, поскольку reply WebApp может не иметь initData. Старый sendData-приём заявок сохранён; ранее выданную клавиатуру можно обновить `/start`. Прямой запуск и меню получают роль с `/me` и автоматически открывают управление. Вкладка «Как клиент» — осознанный выбор представления, без изменения серверных прав (ФТ-23). Любой защищённый API проверяет права независимо от вкладки.

«Мои заявки» в боте и API используют один `list_customer_bookings` с серверным Telegram ID; служебный список показывает все заявки. Синхронизация происходит при открытии/обновлении, без websocket. Аудит выдачи служебного интерфейса содержит только ID, время UTC и точку входа.

## Проверка документов и защита данных

Проверка — предварительная подсказка; решение всегда ручное. Интерфейс DocumentChecker можно заменить внутренней реализацией. Дефолт: Pillow приводит рабочую копию к grayscale/контрасту и ограничивает размер; Tesseract читает `rus+eng` через stdin/stdout без временных файлов. Извлечённый текст остаётся только в памяти и сразу сводится к фиксированным кодам. Документы, текст и исключения провайдера не логируются, сетевого клиента в модуле нет.

Явные признаки студенческого дают `document/student`, другого документа — `document/other`; однотонное изображение — `not_document/unknown`. Недостаточные признаки дают `unknown/unknown`, а не отказ. При бликах, наклоне, недоступности OCR, перегрузке или истечении времени включается ручной fallback. Каждый локальный OCR-процесс ограничен 650 мс, пакет проверки — 2.2 с; допускается не более двух незавершённых пакетов. `DOCUMENT_CHECK_MODE=manual` сразу возвращает ручное ревью. Это предел проверки, без времени загрузки файла, сети, нормализации и транзакции БД.

Вердикты зашифрованы AES-256-GCM тем же отдельным ключом анкеты, с отдельными nonce и AAD `booking:kind:check-v1`. Добавлены nullable `encrypted_check`/`check_nonce`; старые фото читаются как «на ручную проверку». Исправление полей сохраняет результаты неизменённых фото; новые фото получают новую проверку. Отрицательная классификация не удаляет файл и не блокирует существующий PII-процесс. Обычный оператор без PII-доступа видит только статус анкеты: ФТ-16 ограничен более строгим НФТ-12.

НФТ-14 нельзя количественно подтвердить без согласованного порога и репрезентативного разрешённого набора фотографий. Автоматических отказов нет; точность классификации при сложном освещении и наклоне должна быть измерена отдельно. Политика и текст согласия обновлены под локальное OCR; рекомендуется новая env-версия политики.
