## Исправления в приложении

1. `app/miniapp_static/app.js`: методы MainButton `showProgress`/`hideProgress` вызываются только при наличии. В эмуляторе 0.1.1 отсутствие `hideProgress` приводило к исключению в `render()` и прерывало загрузку каталога. После исправления и обновления URL JavaScript проблемный переход повторно прошёл без нового исключения.
2. В том же файле добавлен резервный UUID v4 через `crypto.getRandomValues`, когда `crypto.randomUUID` недоступен. Это нужно для будущего HTTP-запуска по LAN в тестовом Telegram. В браузерном QA `randomUUID` был принудительно отключён до старта приложения; полный путь завершился созданием тестовой заявки №365 без ошибок консоли. Проверено отсутствие ошибки, а не реальная работа на телефоне по LAN.
3. `app/miniapp_static/index.html`: версия JS изменена на `20261026-1`. Повторные проверки выявили, что iframe продолжал использовать старый JS из кеша; после смены URL загружена исправленная версия.
4. `app/bot.py`: явный `TELEGRAM_TEST_ENVIRONMENT=1` переключает фабрику бота на тестовые API/file URL и разрешает HTTP URL Mini App. По умолчанию режим выключен; обычная среда продолжает требовать HTTPS. Уведомления используют ту же фабрику. Это проверено локальными тестами без запросов к Telegram; полноценная проверка с тестовым ботом отложена.

## Исправления и ограничения инструментов

**DevKit:** исходный пакет 0.1.1 рассчитывает HMAC, а затем добавляет поле `signature`. Сервер корректно отвергал такие данные: он, как и установленный aiogram, включает в HMAC все поля, кроме hash. Локальный адаптер `tools/telegram-qa/devkit-sdk.mjs` пересчитывает hash после добавления signature. Серверная авторизация и пакет в node_modules не менялись. После адаптации проверены загрузка своих заявок в iOS- и Android-профилях и отсутствие ошибок консоли в этих сценариях.

**tg-mini-app-emulator:** опубликованный CLI использует `Bun.serve` и падает под Node с `Bun is not defined`. В текущей среде он реально запущен через официальный Bun. Добавлен повторяемый launcher `run-emulator.mjs`. Его SDK не содержит методов индикатора MainButton. Кроме того, Dark Mode затемняет рамку и меняет состояние SDK, но не устанавливает CSS-переменные темы, которые устанавливает официальный Telegram SDK: приложение в этой рамке остаётся светлым. Это ограничение mock, а не подтверждённый дефект темы в реальном Telegram. Светлая и тёмная темы приложения проверены в Vite и DevKit.

**Управление iframe:** чтение состояния, заполнение дат и клики по кнопкам рамки работали, но средство браузерного управления отклоняло некоторые клики внутри cross-origin iframe (`Click target is no longer available`). Для DevKit загрузка заявок дополнительно проверена прямым открытием того же launch URL с тем же SDK и полной перезагрузкой. Не заявляется, что весь процесс бронирования пройден внутри каждой мобильной рамки.

**TMA-Studio:** стартовый экран был прочитан, но средство Windows сообщало о перекрытии окна и невозможности определить foreground process. Вывод окна пользователем на передний план не восстановил ввод. Были завершены созданные в этом проходе экземпляры из `tools/telegram-qa/vendor/studio`; повторный запуск через средство управления остановлен физической клавишей Escape. Дальнейшие действия с окнами прекращены. Проверки приложения внутри Studio не выполнены.
