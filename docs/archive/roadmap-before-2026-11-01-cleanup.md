## Бронирование: удобный сценарий для клиента

**Цель:** клиент оформляет заявку в Telegram без ручного ввода дат, времени и ID оборудования. Основной интерфейс — Telegram Mini App; бот открывает его заметной кнопкой и остаётся доступным для уведомлений и простого резервного сценария.

### 1. Исследование и проектирование UX

- [x] Описать путь клиента от `/start` до подтверждённой заявки, включая пустой каталог, отсутствие свободных экземпляров и отказ менеджера.
- [x] Составить пошаговый опрос: даты и время аренды → доступное оборудование → контактные данные → проверка заказа → отправка заявки. Показывать только вопросы, нужные для текущего шага.
- [ ] Подготовить мобильные макеты и тексты кнопок, подсказок, ошибок и уведомлений. Проверить сценарий на нескольких пользователях до разработки.
- [ ] Согласовать, какие данные клиента обязательны, где показывать стоимость и условия аренды, а также правило расчёта срока ответа после отправки заявки.

### 2. Telegram Mini App — основной способ бронирования

- [x] Добавить кнопку **«Забронировать»** в боте и открыть по ней Mini App. Предусмотреть возврат к боту и понятный путь повторного открытия незавершённого заказа.
- [x] Сделать пошаговую форму с календарём и выбором времени в часовом поясе Москвы; показать занятые интервалы и проверять дату возврата относительно даты выдачи.
- [x] Показывать карточки оборудования на выбранный срок, включая недоступные с пояснением: название, фото (если есть), состояние, цену и итоговую стоимость. Выбор нескольких экземпляров — кнопками, без ввода ID.
- [x] На шаге контактов запросить имя и удобный способ связи; использовать данные Telegram только с понятным объяснением и возможностью исправить их.
- [x] Перед отправкой показать сводку: сроки, оборудование, стоимость и контакты. Отправлять заявку только после явного нажатия **«Подтвердить бронирование»**; защищаться от повторного нажатия.
- [x] После отправки показать номер и статус заявки, ожидание решения оператора, дальнейшие действия и кнопку возврата в чат. Обновлять статус при решении менеджера.
- [x] Проверять Telegram `initData` на сервере и повторно проверять доступность и цену при создании заявки. Размещать Mini App по публичному HTTPS-адресу.

### 3. Кнопки и всплывающие окна

- [x] В боте добавить понятные кнопки для открытия Mini App, просмотра своих заявок и связи с менеджером. Для сценария в чате предусмотреть кнопки **«Назад»**, **«Изменить»** и **«Отмена»** вместо требования повторять `/book` с начала.
- [x] Использовать нативные кнопки Telegram Mini App для основного действия и возврата. Показывать короткие всплывающие подтверждения перед отменой заявки или потерей несохранённых данных.
- [x] Ошибки конкретного поля показывать рядом с ним; всплывающие окна использовать для важных событий, а не для каждого шага формы. После ошибки сохранять введённые данные и давать ясный способ исправления.

### 4. Критерии качества UX и приёмки

- [x] Интерфейс рассчитан на телефон, учитывает светлую и тёмную темы Telegram, safe area, изменение высоты окна и крупные удобные для касания элементы.
- [x] У всех полей есть видимые подписи и примеры ввода; ошибки описаны текстом и указывают, что исправить. Есть состояния загрузки, пустого списка, сбоя сети и повторной попытки.
- [ ] Сценарий доступен с клавиатуры и экранного диктора; фокус, контраст и размеры целей проверены по применимым критериям WCAG 2.2 AA.
- [x] Пользователь может вернуться на предыдущий шаг без потери данных. Сроки, цена и статус сформулированы однозначно.
- [ ] Проверить полный путь на iOS и Android в Telegram, включая медленную сеть, недоступное оборудование, конкурентное бронирование и повторную отправку.

### Реализованный путь клиента

`/start` → «Забронировать» → Mini App → выбор сроков → каталог с доступными и недоступными позициями → корзина → имя и контакт → подтверждение → номер заявки и история в профиле. Доступность повторно проверяется сервером. Команды визуального бронирования открывают Mini App.

### Перед публичным запуском

- [ ] Настроить публичный HTTPS-адрес в `PUBLIC_URL`, домен и Main Mini App в @BotFather.
- [ ] Провести проверку сценария с пользователями, затем поправить тексты и шаги по результатам.
- [ ] Проверить доступность и весь путь на реальных устройствах iOS и Android в Telegram.

### Текущий фокус

Клиентский Mini App и бот запускаются отдельной конфигурацией `compose.miniapp.yaml`; панель сайта оставлена на паузе. Для неё не ведётся дальнейшая разработка до отдельного решения.

## Цикл аренды и документы — реализовано 25.10.2026

- [x] Артикулы, количества, экземпляры с серийными номерами, складскими ячейками и 24-часовым буфером.
- [x] Конкурентное резервирование под PostgreSQL advisory lock и автоматические зависимости комплектов.
- [x] Статусы `pending → confirmed → preparing → ready → issued → return_inspection → returned` с обязательными проверками.
- [x] Автоматическая и ручная комплектация; запрет аккумуляторов ниже 80% здоровья или 95% заряда.
- [x] Возврат, дефектовка, ремонтные тикеты и вывод экземпляра из оборота.
- [x] Ролевая Mini App для клиента, `ADMIN_IDS` и отдельной роли `PII_ADMIN_IDS`.
- [x] Отдельное согласие и анкета, четыре изображения документов, проверка формата/размера и удаление метаданных.
- [x] AES-256-GCM с отдельным ключом анкеты, аудит раскрытия/скачивания/изменения/удаления и служебные блокировка/удаление.
- [x] Очистка через 24 часа для отменённых заявок и через 90 дней после возврата или закрытия ремонта.
- [x] Договор без серийных номеров, акты выдачи/возврата с серийными номерами; генерация DOCX в памяти.
- [x] Alembic-миграция и backfill старых данных по точному совпадению полей.
- [x] Ограничения Nginx для маршрутов документов, `no-store` и заголовки безопасности.
- [x] Интеграционные тесты серверного контура.

Перед включением сбора документов остаются организационные задачи: заполнить данные оператора в `.env`, утвердить политику и отдельное согласие, определить бумажные сроки, допущенных сотрудников, порядок инцидентов и проверить уведомление Роскомнадзора. Полный путь на реальных iOS и Android остаётся ручной приёмкой.
