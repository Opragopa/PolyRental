# PolyRental v0.4 — готовность выпуска

Рабочая версия: `0.4.0-rc.1`. Реализация — в [статусе](../design/v0.4.0-status.md), проверки — в [приёмке](../qa/v0.4.0-acceptance.md). Галочки относятся к локальной реализации; production проверяется отдельно.

## Реализация

- [x] Атомарная генерация/архив PDF, предпросмотр, клиентское скачивание и пять лет хранения.
- [x] Две бумажные точки подписи, доверенные сотрудники, подтверждения клиента, идентичность получателя и возвращающего.
- [x] Частичная выдача экземпляров и элементов комплекта, приложение, ознакомление, фактическая комплектация возврата.
- [x] Исторические акты только в PII-архиве; перенос старых выдач без выдуманного снимка/подписей.
- [x] Владельцы, контакты, особенности, снимки, ущерб/утеря и уведомление сотруднику для связи с владельцем.
- [x] `client_fix` / `manager_edit`, diff, спор, дедлайн/напоминание и защищённые комментарии.
- [x] Подроли, PII-разграничение, жёсткое назначение и явная передача; служебная история без приватного текста.
- [x] Рабочий календарь и внешняя занятость оборудования из ROADMAP.
- [x] Причина отклонения, необязательные напоминания и раздел сотрудника между устройствами.
- [x] Бесплатная аренда, скрытые deprecated-поля, диалоги, фото, свёрнутая история и обновление UI-кеша версией.
- [x] Backfill номеров с короткими транзакциями и параллельной записью.
- [x] Дополнительные серверные/браузерные сценарии и CI-команды для них.

- [x] Загрузка фото моделей в PostgreSQL и пороги контроля хранения.

## Перед production

- [ ] Проверить реальные Telegram iOS, Android и Desktop: весь цикл, медленная сеть, загрузка/предпросмотр PDF, клавиатура и экранный диктор.
- [ ] Проверить доставку уведомлений/SLA в реальные настроенные чаты, мониторинг и задержку подписки Google Calendar.
- [ ] Сверить production SHA, миграции и активные заявки; сделать production backup и проверить восстановление вне рабочей БД.
- [ ] Назначить доверенных подписантов и актуальные подроли; обновить версию согласия и календарные исключения.
- [ ] Подтвердить CI на точном коммите, выполнить поэтапный deploy и бизнес-проверки, сохранить план отката.
- [ ] После этих проверок заменить RC финальной версией и создать тег `v0.4.0` на проверенный коммит.
