# PolyRental v0.4.0 — чек-лист готовности

Этот список показывает оставшиеся работы перед выпуском v0.4.0. Полные требования находятся в [`requirements.md`](../../requirements.md), поэтапный план выкладки — в [`docs/design/rollout-v0.4.md`](../design/rollout-v0.4.md), текущая детализация статуса — в [`docs/design/v0.4.0-status.md`](../design/v0.4.0-status.md).

Галочка означает подтверждённую локальную работу, а не готовность production. Релиз можно объявлять только после выполнения обязательных пунктов, полной приёмки и проверки production на точном коммите.

## Обязательные работы

### Выдача, возврат и документы

- [ ] Подключить генерацию и архивирование PDF-расписки к реальному процессу выдачи.
- [ ] Обеспечить предпросмотр и доступ клиента к сохранённой расписке.
- [ ] Убрать создание новых актов и зависимость выдачи от акта; старые акты оставить только для `PII_ADMIN_IDS`.
- [ ] Реализовать доверенных сотрудников, две точки бумажной подписи и логические подтверждения выдачи/возврата.
- [ ] Зафиксировать получателя и неизменяемое ФИО; отклонять возврат другим человеком.
- [ ] Реализовать частичную выдачу: причины, замены, бейдж, лист-приложение и подтверждение ознакомления.
- [ ] Проверить транзакционность действий и восстановление после сбоев.
- [ ] Подтвердить пятилетнее хранение PDF, удаление ПД и ключей, backup и сохранение метаданных подписания.

### Инвентарь и ущерб

- [ ] Добавить владельца и необязательный контакт с заданными правилами видимости.
- [ ] Реализовать особенности экземпляра, append-only-записи оператора, правки/удаление админом и аудит.
- [ ] Сохранять снимок особенностей при выдаче и сравнивать его при возврате.
- [ ] Различать старые особенности и новый ущерб/утерю; определить путь для старых заявок без снимка.
- [ ] Добавить компактный список замен: до 10 элементов без скролла, далее поиск по ID/названию.

### Заявки, роли и уведомления

- [ ] Реализовать `needs_changes` с `client_fix` и `manager_edit`.
- [ ] Добавить редактирование менеджером, diff, подтверждение/оспаривание, обязательный комментарий и уведомления.
- [ ] Реализовать напоминание за 2 часа и переход в `pending` через 24 часа без ответа.
- [ ] Довести проверки ролей и `PII_ADMIN_IDS` до всех UI, API и bot-входов.
- [ ] Завершить жёсткое закрепление заявки и согласовать его с 10-минутным локом.
- [ ] Проверить, что зашифрованные комментарии и ПД не раскрываются в общей истории.

### UI и совместимость

- [ ] Убрать из пользовательских потоков цены, ставку, условия и устаревшее описание буфера.
- [ ] Привести кнопки, подтверждения и оверлеи к матрицам требований; использовать «Отменить заявку».
- [ ] Проверить фото, просмотр, плотность карточек, touch-targets, клавиатуру и скрытие Telegram ID.
- [ ] Проверить старые анкеты и фото, экранные дикторы, мобильные размеры и реальные Telegram iOS/Android/Desktop.

## Приёмка и выпуск

- [ ] Сверить production commit, версию, миграции, активные заявки и конфигурацию.
- [ ] Создать зашифрованный backup и проверить восстановление.
- [ ] Прогнать серверные, Chromium/WebKit, конкурентные, прямые API и сквозные проверки по разделу 10 `requirements.md`.
- [ ] Выполнить приёмку полного цикла: заявка → анкета → подготовка → выдача → возврат.
- [ ] Проверить уведомления, Google Calendar, аудит, мониторинг и известные ограничения.
- [ ] Обновить `VERSION`, `README.md`, `CHANGELOG.md`, release notes и UI-кеш.
- [ ] Проверить CI на точном коммите и сохранить результаты.
- [ ] Выполнить поэтапный deploy, проверить production и план отката.
- [ ] Только после успешной проверки создать или обновить тег `v0.4.0`.

## Текущий статус

На момент добавления этого списка локальная версия — `0.3.3`; релиз v0.4.0 не готов, production и тег `v0.4.0` не подтверждены.
