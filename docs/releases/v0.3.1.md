# v0.3.1 — рабочее место оператора и проверка анкеты

Дата: 2026-10-26. Базовый выпуск: `f9f5b78` (v0.3.0).

## 1. Результат

Ревью открывается внутри выбранной заявки. Компактный список остаётся виден, а сводка, персональные данные, документы, предварительная проверка, ручное решение, действия и история имеют отдельные блоки. Реквизиты раскрываются в подписанных полях. Следующий шаг соответствует прежней машине состояний, карточка объясняет ограничения и показывает держателя/истечение этапа.

Полные ПД, фотографии и вердикты доступны только `PII_ADMIN_IDS`. История доступна сотрудникам и содержит только разрешённое действие, Telegram ID участника и время. Содержимое документов, OCR, реквизиты, комментарии и поля исправления в историю не передаются.

## 3. Запуск и проверка

Для локальных проверок из корня проекта:

```powershell
docker compose --profile test run --rm --build test
node --test tests/calendar.test.cjs
npm ci --prefix tools/browser-qa
$env:NODE_PATH = './tools/browser-qa/node_modules'
./tools/browser-qa/node_modules/.bin/playwright install chromium webkit
$env:PLAYWRIGHT_BROWSER = 'chromium'
node tests/calendar-ui.cjs
node tests/request-review-ui.cjs
$env:PLAYWRIGHT_BROWSER = 'webkit'
node tests/calendar-ui.cjs
node tests/request-review-ui.cjs
```

В Linux CI установка браузеров выполняется с `--with-deps`. Для установленного Chrome можно задать `PLAYWRIGHT_CHANNEL=chrome` при Chromium-проверке.

Ручная приёмка на тестовых данных:

1. Откройте управление обычным оператором, затем PII-администратором. Сверните/разверните заявки клавиатурой и касанием на узком экране; соседние карточки остаются на месте. У оператора нет доступа к реквизитам, изображениям и вердиктам, в том числе прямым API-запросом.
2. В подтверждённой заявке с отправленной анкетой откройте ревью, раскройте реквизиты и проверьте фотографию. Для нечёткого кадра/сбоя/таймаута видна причина ручной проверки. Подтвердите документы или выберите поля и верните на исправление. Состояние и история обновляются внутри той же заявки.
3. Двумя операторами попробуйте обработать один этап. Видны держатель и время по МСК; конфликт возвращает `409`. После истечения десяти минут карточка показывает истечение. Проверка анкеты не занимает этап следующей подготовки.
4. Пройдите подготовку, проверки, подпись, выдачу и возврат. Преждевременный переход и переход через этап запрещены сервером. История показывает действия и участников без ПД и содержимого документов.
5. Проверьте светлую/тёмную темы, отсутствие горизонтальной прокрутки, подписи полей и размеры кнопок от 44 px. `/health` и Mini App показывают `0.3.1`.

Публикация после проверки: сохраните образы v0.3.0, соберите новые bot/backend и перезапустите их штатным deploy-процессом. `alembic upgrade head` остаётся совместимым; новых миграций нет. Этот выпуск не требует изменения `.env`, ключа шифрования или версии согласия.

## 4. Принятые дефолты

- Accordion на всех ширинах, одна выбранная заявка; история загружается при раскрытии.
- Используются прежние журналы; старые отсутствующие события не восстанавливаются. Участник обозначен Telegram ID, время — МСК.
- Исправление использует `needs_changes`; отдельный окончательный отказ в анкете не вводится.
- Отсутствие или сбой автопроверки сохраняет ручной сценарий. Вердикт не подтверждает и не отклоняет анкету автоматически.
- API изменён только аддитивно: служебная история и `operation_lease_state`; `operation_lease` сохраняет прежний контракт.
- Локальный таймер показывает истечение известного захвата. Изменения другого оператора поступают после обновления данных; сервер всегда проверяет актуальное состояние.

Обоснование: [ADR 0002](../adr/0002-v0.3.1-request-review.md).

## 5. Проверки и результаты

- Docker, PostgreSQL `polyrental_test`, Alembic: **135 pytest-тестов прошли**. Единственное предупреждение — устаревший alias `BlockingPortal` в зависимости Starlette/AnyIO.
- **3 unit-теста календаря Node прошли**.
- **42 браузерных сценария прошли**: по 10 сценариев проверки заявки и 11 календаря/ролей/SDK в Chromium и WebKit. Новый набор покрывает 320 px/light, 390 px/dark и 1024 px; keyboard/focus, цели от 44 px, отсутствие переполнения, сохранение прокрутки после действия, отсутствие PII-запросов у оператора, approve/correction, поздние ответы анкеты/раскрытия, закрытие предпросмотра, истечение захвата без обхода предпосылок и обновление захвата после полной/частичной проверки экземпляров.
- `node --check`, Python `compileall` и `git diff --check` прошли. Независимая проверка кода не выявила обхода PII-прав, серверных переходов или блокировок.
- Визуально просмотрены [320 px/light](../qa/v0.3.1-review-320-light.png), [390 px/dark](../qa/v0.3.1-review-390-dark.png) и [1024 px](../qa/v0.3.1-review-1024-light.png). Все данные и изображения в этих проверках синтетические.

Локальные браузерные проверки использовали Playwright 1.62.1, установленный Chrome и WebKit из `tools/browser-qa/.browsers` (`PLAYWRIGHT_BROWSERS_PATH`). CI устанавливает оба браузера из lockfile. Удалённый CI и реальные Telegram-клиенты учитываются отдельно от локальных проверок; статус CI следует проверять на текущем head PR.

## 6. Риски и откат

- История ограничена ранее записанными действиями, не является неизменяемым юридическим журналом. Ошибки загрузки истории не должны блокировать остальную заявку.
- Открытый интерфейс может устареть из-за другого оператора; backend отклонит неверный переход или конфликт блокировки. Обновите список и повторите разрешённое действие.
- Browser-моки проверяют интерфейс и роли, но не заменяют реальный Telegram, проверку screen reader и всех пользовательских тем. Автопроверка документа остаётся эвристической.
- Откат: остановите новые bot/backend и верните сохранённые образы v0.3.0 либо соберите их из `f9f5b78`; перезапустите штатным Compose-процессом. Downgrade БД и восстановление backup не нужны. Новые заявки, статусы и ручные решения остаются в прежних таблицах. Проверьте `/health`, старую заявку и доступ PII-администратора после отката.
