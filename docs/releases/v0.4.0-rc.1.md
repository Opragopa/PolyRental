# 0.4.0-rc.1 — кандидат для приёмки

Завершает функциональные блоки финальных требований v0.4 и дополнительные задачи ROADMAP. Публикация production и окончательный тег этим документом не подтверждаются.

- Единая PDF-расписка вместо новых актов, подтверждения сторон, доверенные подписанты, пятилетний архив и перенос старых выдач.
- Частичная выдача техники и комплектации, снимки особенностей, владельцы и учёт ущерба/утери.
- Изменение заявки клиентом/менеджером, diff, спор, сроки ответа, приватные комментарии и причина отклонения.
- Рабочий календарь, внешняя занятость, необязательные напоминания и серверное сохранение раздела сотрудника.
- Фото моделей с миниатюрами в БД и пороги мониторинга хранения.
- Проверки ролей, жёсткое назначение, обновлённый UI и проверки конкурентных действий/восстановления.

## Обновление

1. Сохранить образы, SHA, конфигурацию и проверенную зашифрованную production-копию. Тестовый seed работает только с `polyrental_test`.
2. Применить `alembic upgrade head` (`20261030_33`). Новые миграции сохраняют старые документы. Изменение ранней миграции нумерации влияет на новые установки/старые пути обновления и не запускается повторно на уже обновлённой БД.
3. Обновить backend, бот и UI совместно; установить новую `PRIVACY_POLICY_VERSION`, проверить рабочий календарь и список доверенных сотрудников.
4. Проверить новые и старые активные заявки по [плану выпуска](../design/rollout-v0.4.md). `/health` не является полной приёмкой.

Откат после новых операций требует остановки записи и согласования кода/данных. Старый код не знает о частичной выдаче, внешней занятости и подтверждениях. Аддитивные таблицы и архивы при downgrade сохраняются.
