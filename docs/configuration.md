# Настройки окружения PolyRental 0.5.3

Сверено с кодом 05.11.2026. `.env.example` — образец, `.env` — локальные значения и секреты, исключённые из Git. Обновление образца не меняет рабочий `.env`. Файл с точным именем `env.example` без начальной точки не используется.

## Как применяются значения

Docker Compose читает `.env` для подстановок и передаёт его боту/Mini App через `env_file`. Секция `environment` имеет приоритет: `DATABASE_URL` собирается из `POSTGRES_PASSWORD` с хостом `db`; `REDIS_URL` и `PUBLIC_URL` берутся из одноимённых настроек. Переменная в окружении оболочки имеет приоритет над `.env` при подстановке Compose.

После изменения `.env` пересоздайте нужные сервисы: обычный `restart` не перечитывает окружение контейнера.

```powershell
docker compose -f compose.yaml -f compose.miniapp.yaml up -d --no-deps --force-recreate bot miniapp
```

Команда применяется к приложению; миграции и обновление образа выполняются отдельно по [README](../README.md). Существующие ключи шифрования и пароль действующей БД нельзя просто заменить как обычную настройку: это требует отдельного переноса данных/учётных данных. Изменение `POSTGRES_PASSWORD` не меняет пароль уже созданного PostgreSQL-пользователя.

При прямом запуске Python на хосте приложение и скрипты не загружают `.env` автоматически: переменные должны присутствовать в окружении процесса. Хост PostgreSQL `db` разрешается внутри Compose; для запуска с хоста нужен доступный хост и порт БД.

## База, бот и доступ

| Параметр | Что настраивает |
|---|---|
| `DATABASE_URL` | SQLAlchemy DSN PostgreSQL. При прямом запуске задаётся явно; основной Compose переопределяет его строкой с `POSTGRES_PASSWORD`. |
| `POSTGRES_PASSWORD` | Пароль PostgreSQL при создании базы и в DSN контейнеров приложения. `polyrental` в образце — локальное значение. |
| `REDIS_URL` | Redis для публичного кэша; образец `redis://redis:6379/0`. Ошибка Redis включает чтение PostgreSQL. Основной Compose подставляет локальный Redis и при пустом значении. |
| `BOT_TOKEN` | Токен бота из BotFather; нужен боту, проверке подписей и уведомлениям. |
| `BOT_USERNAME` | Имя бота без `@`, для виджета входа и ссылок. |
| `PUBLIC_URL` | Внешний базовый адрес без `/miniapp`, query и fragment. Локально `http://localhost:8000`; production `https://polyrental.opragopa.com`. Нужно согласовать с Nginx, Main Mini App и доменом входа в BotFather. |
| `ADMIN_IDS` | Обязательные положительные Telegram ID сотрудников через запятую. Подроли хранятся в `StaffRole`, назначаются в интерфейсе. |
| `PII_ADMIN_IDS` | Независимый список допущенных к полным ПД, фото и проверке анкеты. Пустой список не даёт PII-доступа; для сбора анкеты нужны заполненные настройки. |
| `SESSION_SECRET` | Случайный секрет подписи сессии сайта, не менее 32 символов. Смена делает прежние сессии недействительными. |
| `ICAL_TOKEN` | Отдельный случайный секрет iCalendar-ссылки, не менее 32 символов. Смена требует заново подключить подписку. |
| `TELEGRAM_AUTH_MAX_AGE` | Максимальный возраст Telegram `initData` и данных входа, секунды; по умолчанию `86400`. Сессия сайта отдельно имеет фиксированные 24 часа. |
| `TELEGRAM_TEST_ENVIRONMENT` | Только `1` включает тестовый Bot API и разрешает HTTP Mini App для отдельного тестового бота; для production `0`. |
| `HTTPS_PROXY` / `https_proxy` | Необязательный прокси запросов бота. `HTTPS_PROXY` имеет приоритет. Пример закомментирован; это не настройка системного прокси всех сервисов. |

## Анкеты, документы и резервные копии

| Параметр | Что настраивает |
|---|---|
| `PII_MASTER_KEY` | 32 случайных байта в base64url для шифрования анкет, документов, приватных комментариев и запросов на изменения. Потеря ключа делает сохранённые данные нечитаемыми. |
| `BACKUP_MASTER_KEY` | Другой 32-байтный base64url-ключ для зашифрованных резервных копий. Хранить отдельно от копий; нужен и при восстановлении. |
| `OPERATOR_NAME` | Наименование оператора обработки данных в согласии и документах. Это не имя текущего сотрудника. |
| `OPERATOR_ADDRESS` | Адрес оператора для текста согласия. |
| `OPERATOR_CONTACT` | Контакт оператора по вопросам обработки данных. |
| `PRIVACY_POLICY_VERSION` | Версия согласия, по умолчанию `2026-10-30-v4`; при изменении согласия задаётся новая версия. |
| `DOCUMENT_CHECK_MODE` | `local` — Pillow + локальный Tesseract; `manual` — только ручная проверка. Автопроверка предварительная и не одобряет документы вместо сотрудника. |
| `DADATA_API_KEY` | Необязательный ключ серверных подсказок адресов. Без ключа остаётся ручной ввод. |
| `RECEIPT_FONT_PATH` | Путь к TTF внутри среды приложения для совместимого PDF-генератора. Пример закомментирован, стандартный путь — DejaVuSans в Docker. Новые расписки формируются в DOCX. |

Каждый ключ можно отдельно сгенерировать локально командой `python -c "import secrets; print(secrets.token_urlsafe(32))"`. Пример не содержит действующих ключей.

`BACKUP_MASTER_KEY` читается из окружения запуска `scripts/backup_encrypted.py` и `scripts/verify_encrypted_backup.py`. Простое заполнение `.env` не запускает резервное копирование и не передаёт ключ произвольному Python-процессу на хосте. Хранение копий — параметр скрипта `--retention-days` (по умолчанию 30), а не отдельная переменная приложения.

## Календарь, уведомления и служебные параметры

| Параметр | Что настраивает |
|---|---|
| `NON_WORKING_DATES` | Дополнительные нерабочие даты планового календаря: `YYYY-MM-DD` через запятую. |
| `WORKING_DATES` | Рабочие исключения в том же формате; имеют приоритет над выходными и закрытыми датами. Часы остаются заданными в коде. |
| `ENFORCE_HANDOVER_SCHEDULE` | `true` проверяет рабочий день/часы плановых дат. `false`, `0`, `no` отключают это ограничение; фактические этапы доступны круглосуточно и при `true`. |
| `SLA_HOLIDAYS` | Праздники расчёта SLA, отдельный список `YYYY-MM-DD` через запятую; не меняет календарь бронирования. |
| `SLA_SHARED_CHAT_ID` | Числовой ID общего Telegram-чата эскалаций; пусто — общий чат отключён. Для группы ID обычно отрицательный; бот должен иметь доступ к чату. |
| `UNDO_DELETE_SECONDS` | Окно отмены скрытия заявки, по умолчанию 5 секунд; приложение ограничивает диапазоном 1–30. |
| `RELEASE_CHANNEL` | `@channel_name` либо числовой ID канала обычных релизов. Боту нужны права публикации. Пусто — автоматические посты отключены, объявления внутри приложения остаются. Источник текста — `app/assets/releases.json`, журнал `release_publications` предотвращает повторы. Hotfix не создаёт отдельный пост. |
| `DATABASE_WARN_GIB` | Порог размера БД для `scripts/check_storage.py`, по умолчанию 5 ГиБ. |
| `BACKUP_WARN_GIB` | Порог размера каталога копий для того же скрипта, по умолчанию 50 ГиБ. |
| `BACKUP_MAX_AGE_HOURS` | Максимальный возраст последней копии для проверки, по умолчанию 26 часов. |

Пороговые переменные сами по себе не запускают мониторинг: нужно отдельно запускать `python scripts/check_storage.py <каталог-копий>`. Скрипт также читает окружение процесса. Рабочие часы выдачи/приёма, SLA-нормативы, сроки хранения ПД и мягкая блокировка не настраиваются через этот образец — соответствующие правила заданы в коде.

## Отдельная приёмка и GitHub Actions

`.env.acceptance.example` предназначен только для отдельного бота, домена, ключей и Compose-проекта `polyrental-acceptance`. `compose.acceptance.yaml` задаёт собственный `DATABASE_URL`; Redis и публикация релизов по умолчанию не подключены. Запуск — через `scripts/start-acceptance.ps1`. [Инструкция](qa/acceptance-environment.md).

В GitHub Actions задаются отдельно: **Secret** `DEPLOY_PATH` (путь к production-клону на self-hosted runner) и **Variable** `DEPLOY_ENABLED=true`. В `.env.example` они не добавляются. `QA_HOST`/`QA_PORT` используются только локальным `scripts/qa_server.py`; переменные Playwright и `POLYRENTAL_TEST_REDIS_URL` относятся к тестам.

Коммиты `d1ce885` и `74d07fc` не меняли `.env.example`. Последнее добавление до этой актуализации — `RELEASE_CHANNEL` в `d207dac`; новые запросы клиента и публичные имена используют прежние ключи и не требуют новых обязательных переменных.
