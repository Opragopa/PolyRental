## Восстановление Docker и итоговый прогон

Предыдущий прогон остановился без отчёта: Docker API возвращал 500, журнал backend сообщал `no route to host` до Linux-движка. Попытка использовать отдельный Debian также завершилась `Wsl/Service/WSAETIMEDOUT`, рабочий `/health` не отвечал.

Пользователь разрешил перезапуск Docker Desktop. Штатная команда завершилась по тайм-ауту; зависшие процессы Docker были остановлены вместе с его дистрибутивом `docker-desktop`. Новый запуск блокировался недоступным служебным сокетом. Каталог с единственным пустым `engine.sock` сохранён как `C:\Users\drago\AppData\Local\docker-secrets-engine-stale-20261101-1735`, после чего Docker создал новый сокет и успешно запустился. Другие WSL-дистрибутивы не останавливались; контейнеры, тома и учётные данные не удалялись.

Прежние контейнеры БД, бота и Mini App запущены на существующих образах. Рабочий `/health` подтвердил `{"status":"ok","version":"0.4.5"}`. Нагрузка движка после восстановления была нормальной; временный остановленный контейнер `polyrental-docx-qa` удалён.

Итоговый прогон выполнен только на `polyrental_test`:

```powershell
docker compose run --rm --no-deps -v C:/PROJECTS/PolyRental:/app test sh -c "alembic upgrade head && pytest -q --junitxml=/app/tmp/booking-fixes/pytest-final.xml"
```

Все 255 проверок прошли, включая последние изменения: неблокирующую сериализацию карточек в одном event loop, обновление прежних карточек без push неответственным сотрудникам и фильтрацию истории по ID из ссылки бота.

Новая версия **не развёрнута**. Перед выпуском остаются резервное копирование рабочей БД, применение миграции, обновление обоих сервисов и проверка реальной доставки Telegram на тестовой заявке.
