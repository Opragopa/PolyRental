## Достоверные автоматические результаты

Первый удалённый прогон GitHub Actions для [PR №1](https://github.com/Opragopa/PolyRental/pull/1) прошёл: [run 40390942992](https://github.com/Opragopa/PolyRental/actions/runs/40390942992), Test и Calendar and mobile UI — success, Deploy production — skipped. Следующие изменения добавляют WebKit, нативную MainButton и регрессионный benchmark; результат последнего head проверяется отдельно.

Обе мобильные конфигурации Playwright — Chromium и WebKit 26.5 — локально прошли по 11 сценариев (22 всего). Проверяются touch/mobile viewport, 320–430 px, обе темы, МСК при другом часовом поясе устройства, навигация и сброс, роли, PII-ревью, управление нативной MainButton и событие themeChanged. WebKit — проверка совместимости движка, а не подтверждение запуска на физическом iPhone в Telegram.

## Проверка документов без реальных фото

Пользователь подтвердил отсутствие разрешённого набора фото. Поэтому используются 72 воспроизводимых синтетических изображения: по 24 студенческих, других документов и не-документов. В каждой группе — четыре макета и шесть условий: обычное фото, плохое освещение, блик, наклон 12°, перспектива, размытие. Никаких фотографий людей, реквизитов или OCR-текста в отчётах нет. Изображения генерируются только в памяти.

До выравнивания наклона: [baseline JSON](v0.3.0-document-benchmark-baseline.json). После: [итоговый JSON](v0.3.0-document-benchmark.json). Хеш набора совпадает: `41f77456c34bccc698d1aadd2b835206296519818f92e3fff1002511b482e718`.

| Метрика | До | После |
|---|---:|---:|
| Распознан студенческий | 20/24 (83.33%) | 24/24 (100%) |
| Документы ошибочно помечены «не документ» | 0/48 | 0/48 |
| Другие изображения ошибочно помечены «студенческий» | 0/48 | 0/48 |
| Строгая точность document/not_document, unknown считается ошибкой | 63.89% | 75% |
| p95 времени проверки одного изображения | 0.1565 с | 0.1601 с |

18/72 случаев остаются `unknown`: это неоднотонные не-документы. Это честно учитывается в точности, а не исключается из знаменателя. Все результаты, включая положительные, требуют ручного решения. На наклонённых синтетических документах выравнивание устранило пропуски; это не оценка качества на реальных студенческих билетах.

Инженерные пороги регрессии заданы до повторного измерения: false_non_document=0, false_student=0, student_recall≥80%, p95<3 с. Это пороги синтетического теста, не согласованный SLA на реальных фото. Они не изменяют ручную модерацию. Без реального набора нельзя подтвердить долю ошибок при бытовом освещении и наклоне.

Повторить:

```powershell
docker compose --profile test run --rm -v "${PWD}:/app" test python scripts/benchmark_documents.py --output artifacts/document-benchmark.json
```

Для будущего локального согласованного набора положите файлы в игнорируемую `local-qa-data/`, не добавляйте их в Git. Manifest — JSON-массив объектов с `path` (относительно manifest), `label` (`student`, `other`, `not_document`), `condition` (`clean`, `low_light`, `glare`, `rotation`, `perspective`, `blur`). Запуск с `--manifest local-qa-data/manifest.json --approved-local-dataset --output artifacts/private-benchmark.json` допустим после разрешения владельца данных. Пути за пределы каталога запрещены; в отчёте используются только номерные ID, кодовые метки и метрики. Согласованные реальные пороги и репрезентативность набора должны быть заданы отдельно.

## Реальный iPhone: протокол приёмки

Пользователь сообщил, что доступен iPhone. Проверка ещё не выполнена, модель/iOS/Telegram неизвестны. Android-устройства нет; Chromium не считается физической Android-проверкой.

Условие запуска: публичный HTTPS должен обслуживать именно проверенный head v0.3.0. Production пока работает на прежнем образе; открыть там Mini App и увидеть старую версию не означает проверить v0.3.0. Сначала требуется отдельный QA-стенд либо согласованное развёртывание прошедшего CI head. Открытие в Safari само по себе не заменяет запуск внутри Telegram.

Запишите модель iPhone, версию iOS, версию Telegram, метку v0.3.0 и commit развёртывания. После каждого шага отметьте PASS/FAIL и короткое наблюдение; не включайте реальные документы, ФИО или контакты других людей в доказательства.

| ID | Действие | Ожидаемый результат |
|---|---|---|
| IOS-01 | Открыть приложение кнопкой бота и затем прямым Mini App запуском | Правильная серверная роль; у сотрудника управление, у клиента календарь. Сотрудник может выбрать «Как клиент». |
| IOS-02 | Открыть первый шаг при обычном масштабе, без прокрутки | Календарь, время и нативная кнопка доступны. Горизонтального скролла нет. Прошедшие/закрытые дни disabled. |
| IOS-03 | Выбрать начало и конец двумя тапами | Начало выделено после первого тапа, диапазон после второго; доступны два времени с датами. |
| IOS-04 | Выбрать один день; задать конец до начала, затем после начала | Неверный период блокирует MainButton и показывает причину; правильный разблокирует. Есть МСК. |
| IOS-05 | Перейти к технике, вернуться, открыть «Мои заявки», вернуться | Даты и времена сохраняются. «Сбросить» очищает диапазон и блокирует продолжение. |

Минимальный формат фактического результата:

```text
Устройство: <модель>, iOS <версия>, Telegram <версия>
Среда: <QA/production>, release 0.3.0, commit <SHA>
IOS-01 PASS/FAIL — наблюдение
...
IOS-09 PASS/FAIL/NOT RUN — наблюдение
```

До получения этих фактических данных физический iPhone отмечается PENDING, Android — NOT AVAILABLE, точность на реальных документах — NO APPROVED DATASET. Эти статусы не заменяются результатами эмуляции или синтетического benchmark.
