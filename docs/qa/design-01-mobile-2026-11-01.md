# DESIGN-01 — мобильная итерация 01.11.2026

Основной экран: 440 × 956 CSS px при DPR 3, снимки 1320 × 2868. Дополнительно 320 px и тёмная тема. Это браузерная эмуляция, не проверка физического iPhone / Telegram iOS.

## Исправления приложения

- Получение и возврат расположены рядом; условия и быстрый срок доступны для раскрытия.
- В управлении каталогом поиск стоит перед действиями; импорт и справочные зависимости раскрываются отдельно.
- Редактор артикула/экземпляра открывается вместо списка, получает фокус и прокрутку к началу формы.
- Дополнительные действия экземпляра свёрнуты, изменение остаётся доступным. Кнопки создания не меньше 44 px.
- В заявке добавлен переход к действиям из блока следующего шага.
- Исправлены подсказки оператору, упоминание оплаты, подпись фильтра ответственного и русские названия профилей проверки (UX-003).
- Учтён верхний отступ Telegram safe area, поля на мобильном имеют размер шрифта 16 px.

## Проверки

- tests/design-mobile-ui.cjs: 28 состояний Chrome и 28 WebKit. Переполнение, ошибки JS, фокус редактора, высота кнопок, русские названия профилей; клиентские и служебные сценарии, частичная выдача, диалоги.
- completion-ui: 12 Chrome; design-flow-ui: 4 Chrome; request-review-ui: 14 Chrome.
- node --check, git diff --check.
- Снимки: tmp/design-mobile/after и tmp/design-mobile/webkit. Визуально просмотрены даты, каталог и редактор; остальные состояния проверены автоматически.
- API в проверках подменён синтетическими данными. Рабочая БД и развёрнутая версия не изменены.

## Figma

[Страница DESIGN-01](https://www.figma.com/design/iuCaXkl5P9nHYRTZ2wkDag/PolyRental?node-id=31-14).
Созданы 28 связанных сценарных экранов и два варианта каталога (320 px, тёмная тема). Сохранены старые страницы. Используются редактируемые тексты, auto layout, существующие компоненты кнопок и цветовые переменные PolyRental.

Это интерактивная схема сценариев, а не точная копия HTML: поля показывают примеры состояний, скачивание демонстрационное, реальные персональные данные отсутствуют. Основные переходы: оформление, исправление анкеты, частичная выдача и DOCX, подтверждение получения, возврат, обработка сотрудником, конфликт, отмена, создание категории. Два стартовых потока: клиент и сотрудник.

## Остаток DESIGN-01

Для полного закрытия исходной цели нужны точная синхронизация компоновки всех экранов Figma с приложением, интерактивный выбор произвольных дат/количества и подробные варианты полей анкеты/загрузки. Текущая страница служит проверяемой схемой переходов. Пользовательские сессии, экранная клавиатура и VoiceOver на реальном устройстве остаются QA-01/QA-03. DESIGN-01 целиком не закрыт.
