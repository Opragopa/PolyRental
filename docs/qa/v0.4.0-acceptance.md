Браузеры используют подписанные роли и данные через синтетические перехваты; это проверка интерфейса, а не доказательство доставки Telegram Update.

## Воспроизведение

```sh
docker compose run --rm --build test
python scripts/verify_test_restore.py --seed-synthetic --fresh-migrations
node --test tests/calendar.test.cjs
npm ci --prefix tools/browser-qa
```

В CI оба движка запускаются в образе Playwright версии из `package-lock.json`. Локально установить Chromium/WebKit либо использовать установленный Chrome через `PLAYWRIGHT_CHANNEL=chrome`. Установить `NODE_PATH=./tools/browser-qa/node_modules`, `PLAYWRIGHT_BROWSER=chromium` или `webkit` и выполнить каждый из семи `tests/*-ui.cjs`, перечисленных выше. На Windows указать `PLAYWRIGHT_BROWSERS_PATH=./tools/browser-qa/.browsers`, если браузеры установлены туда.

Команда восстановления запускается после тестов, использует только `db_test`, создаёт БД с уникальными именами и удаляет их после проверки. Синтетический seed запрещён для любого имени БД, кроме `polyrental_test`. Сырые dump-файлы на диск не записываются. Локальные логи и изображения находятся в игнорируемой `artifacts/v040/`, не входят в коммит.
