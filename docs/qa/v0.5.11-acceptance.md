13 ноября 2026, МСК. Согласованный объём реализован и установлен только в [тестовом боте](https://t.me/testrentoprabot), публичный адрес — `https://testing.cloudopragopa.online`.

## Что изменилось

| Замечание | Реализация |
|---|---|
| Drag-and-drop фото | Общая область для всех image-input: модели, категории, документы, повреждения. Одно фото, превью, ошибка формата/размера, сохранение прежней цепочки обработки. |
| Заметное приглашение к выдаче | Окно + постоянная карточка + отдельное Telegram-сообщение. Показ подтверждается явно; загрузка уведомления не считается прочтением. Готовность до начала периода приглашает в согласованное время. |
| Неясно, что делать после анкеты | Собственные активные заявки над каталогом с текущим следующим действием. Проверенная анкета означает ожидание подготовки; готовность к выдаче — отдельный этап. |
| «Получил» не нужен | Кнопки убраны из чата и Mini App; старые действия отклоняются без изменения данных. Выдача, архив расписки и авторство сотрудника сохранены. |
| Возврат глубоко в карточке | Кнопка «Сдать оборудование» над каталогом и в главном меню бота. Для нескольких аренд выбор заявки; перед приёмкой — подтверждение физической передачи сотруднику. |
| Особенности оборудования | Отдельный блок с известными особенностями, комплектом и исключениями частичной выдачи. Готовая/выданная заявка читает сохранённый снимок. |
| Кнопки в текстовом боте | Контекстные кнопки в карточках и уведомлениях, активные заявки при `/start`, быстрый возврат, связь с оператором, ссылка непосредственно на защищённую анкету. |
| «Позвонить и забронировать» | По согласованию не добавлено. |

В административных настройках добавлена вкладка «Выдача и возврат». Место получения и инструкция пока пусты: точный адрес пользователь не задавал. Юридический адрес не копировался. До заполнения клиент может уточнить место у оператора.

## Ручной пример

В каталоге найдите **«ТЕСТ 0.5.11»**, затем самостоятельно оформите заявку:

1. Камера для проверки особенностей — **2 шт.** Одна без известных особенностей, у второй отмечена царапина.
2. Свет с неполным комплектом — **1 шт.** При подготовке сотрудник отмечает чехол отсутствующим.
3. Микрофон для частичной выдачи — **1 шт.** При подготовке сотрудник фиксирует невыдачу микрофона.

Пройдите анкету, готовность, выдачу и возврат; сравните особенности и исключения в заявке, чате, расписке и осмотре. Демо-заявки за пользователя не создавались, реальные персональные данные не использовались в автоматических тестах. Техника создана скриптом `scripts/seed_acceptance_0511.py`, который запрещает работу вне отдельной базы приёмки.

Для обновления ранее показанной клавиатуры чата отправьте боту `/start`. Проверка физических Telegram iOS/Android и реальной доставки уведомления клиенту остаётся ручной приёмкой.

Снимки: `artifacts/release-0511/`, в частности `chromium-features.png` и `chromium-home.png`.

## Исправление навигации текстового бота

После замечания о повторных сообщениях добавлен общий рендер клиентского экрана. Начальная команда создаёт сообщение; inline-переходы по списку, заявке, особенностям, страницам комплектации, подтверждениям и просмотру изменений редактируют его текст и кнопки. Ввод нового текстового ответа остаётся отдельным шагом переписки.

Ответ Telegram `message is not modified` обрабатывается без нового сообщения. Если Telegram не разрешает редактирование старого или удалённого сообщения, создаётся одна замена с попыткой убрать старые кнопки. Ошибки, не связанные с редактированием, не скрываются отправкой дубля.

## Заявка без предварительного сбора контактов

В приложении убраны поля имени/контакта в подборке и проверке заявки; текстовый сценарий после выбора оборудования сразу переходит к проверке. Начальное имя — ник Telegram, при отсутствии ника — имя профиля, контакт — Telegram. Сервер получает эти данные из аутентифицированного пользователя, без обязательных полей в новом запросе; прежний формат API совместим.

В анкете добавлен обязательный телефон (10–15 цифр) с серверной проверкой и нормализацией. Отправка анкеты в одной транзакции обновляет ФИО и телефон текущей заявки. Следующие заявки используют данные собственной сохранённой анкеты в пределах существующих правил хранения; данные другого пользователя не подставляются. Старые анкеты без телефона остаются читаемыми; при следующей отправке формы телефон нужно заполнить.

Проверки: полный серверный набор — 465 passed; дополнительные сценарии создания по Telegram и перехода к данным анкеты включены в последующие 110 и 35 успешных проверок (наборы пересекаются). Создание без username, отсутствие контактов в запросе, обязательный телефон, принадлежность анкеты, повторное бронирование и текстовый сценарий проверены отдельно. Booking-submit, lifecycle анкеты и согласие проверены в Chrome/WebKit; подборка, настольное время, вход на сайте, взаимодействия и регрессии навигации — в Chrome.

## Единая карточка профиля и блюр

Карточка Telegram стала заголовком закрытого по умолчанию блока с анкетой. Раскрытие показывает подписи и заглушки с CSS blur; реальный запрос личных данных выполняется только по нажатию на любое скрытое поле. Один запрос показывает все сохранённые поля, редактирование и повторное скрытие. Сворачивание, уход из профиля и устаревший ответ не раскрывают данные повторно. Заглушки доступны с клавиатуры, значения не попадают в разметку до запроса.

Поддержка на мобильной ширине занимает всю доступную область страницы, содержимое центрировано. Ширина учитывает место полосы прокрутки. Проверены support-ui и профиль/onboarding в Chrome/WebKit (320, 390, 1440; светлая и тёмная темы), раскрытие с клавиатуры, редактирование, скрытие при навигации и поздний ответ после сворачивания. Дополнительно Chrome: ui-ux-regressions и frame-style-ui. Снимки просмотрены в artifacts/profile-disclosure-0511/.

При быстрой навигации незавершённая анимация раскрытия карточки отменяется перед сбросом `open`, поэтому следующий вход позволяет открыть профиль с первого нажатия. Этот случай обнаружен и проверен сценариями profile-onboarding-ui в обоих движках.


### Уточнение вида блюра

По уточнению пользователя заглушки удалены. При раскрытии карточки запрашиваются реальные поля анкеты и сразу отображаются с блюром только на значениях. Нажатие на поле меняет CSS-состояние существующих строк; заголовки, текст, размеры и расположение одинаковы до и после раскрытия. Пустые поля не добавляются. Кнопки занимают одинаковое место в обоих состояниях. При сворачивании и навигации данные удаляются из DOM; поздний ответ игнорируется. Блюр — визуальное скрытие уже загруженных данных.

Profile-onboarding-ui прошёл в Chrome и WebKit: сравнение текста, координат и высоты каждой строки, сохранение узлов при снятии блюра, один запрос на загрузку, редактирование, повторное скрытие и поздний ответ после закрытия. Просмотрены снимки artifacts/profile-real-blur-0511/.


## Обновление кэша iPhone / Telegram WebView

После сообщения о старом интерфейсе проверены локальный и публичный HTTPS-адреса: оба отдавали актуальный HTML с `no-store`, но URL JS/CSS оставались прежними внутри версии 0.5.11. Теперь HTML содержит SHA-256 содержимого каждого JS/CSS в query-параметре, а статические ответы (включая 304) получают `no-cache, max-age=0, must-revalidate`. Меню тестового бота открывает URL с идентификатором текущей сборки. Версия продукта остаётся 0.5.11.

14 серверных проверок прошли: новый адрес после изменения файла без смены версии, стабильность неизменённого CSS, реальные заголовки 200/304 и совместимость входа. Повторное открытие на физическом iPhone остаётся пользовательской приёмкой. Уже открытый WebView требуется полностью закрыть и открыть снова.
