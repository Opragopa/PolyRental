02.11.2026, локальный Docker, отдельная PostgreSQL `polyrental_test`; синтетический каталог, 51 артикул по одному экземпляру, без пересекающихся броней. Это сравнение одного запуска, а не оценка production-нагрузки.

| Реализация | SELECT | Время одного вызова |
| --- | ---: | ---: |

Проверка в `tests/test_availability_snapshot.py` дополнительно сравнивает результат с исходным расчётом резервов при замене, просроченной выдаче и внешней блокировке. Отдельно проверяется, что число SELECT не увеличивается при добавлении артикулов. Миграция `20261102_35` добавляет индексы для отбора броней по статусу и интервалу, активных строк по артикулу и доступных экземпляров по артикулу. Выигрыш индексов на репрезентативном объёме production ещё требуется измерить отдельно.

Повторное локальное измерение с Redis и ревизией PostgreSQL, на 51 синтетическом артикуле: прямое чтение — 5 SELECT / 27,4 мс; первый запрос с пустым кэшем — 6 SELECT / 31,6 мс; повторный запрос — 1 SELECT / 1,1 мс. По одному запуску нельзя оценивать задержку на production. Ревизия обновляется в транзакциях записи; её нагрузку и возможное ожидание блокировки необходимо измерить на репрезентативной параллельной нагрузке перед выпуском.
