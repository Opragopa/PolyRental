# План оптимизации производительности PolyRental

> Составлено: 2 ноября 2026 года
> Контекст: FastAPI + PostgreSQL + Telegram Mini App

## Приоритет 1 — сделать в первую очередь

1. **Устранить N+1-запросы и добавить индексы.**
   - В расчёте доступности каталога выполняются повторные запросы для каждого артикула.
   - Перейти на пакетные выборки по артикулам.
   - Добавить составные индексы для частых выборок бронирований и занятости по `article_id`, статусу и интервалам дат.

2. **Добавить пагинацию API.**
   - Нужна для админских заявок, каталога, истории действий и обращений в поддержку.
   - Использовать параметры `limit` и `cursor` (или `offset`) и возвращать метаданные следующей страницы.

3. **Кэшировать часто используемые данные в Redis.**
   - Кандидаты: каталог, категории, расписание, краткоживущие результаты availability.
   - Инвалидировать кэш после бронирования и изменения оборудования.

4. **Перенести тяжёлые задачи в очередь.**
   - Генерация PDF/DOCX, отправка уведомлений, импорт CSV и потенциальная проверка документов.
   - Использовать очередь на базе Redis; FastAPI `BackgroundTasks` оставить только для лёгких некритичных задач.

5. **Включить кэширование и сжатие статики.**
   - Для версионированных CSS/JS/PDF.js и изображений отдать долгий `Cache-Control: public, max-age=31536000, immutable`.
   - Включить Brotli (или Gzip) в Nginx для JS, CSS, JSON, SVG и шрифтов.

6. **Ленивая загрузка тяжёлых компонентов.**
   - Загружать PDF.js и его worker только при открытии предпросмотра документа.
   - Это важнее общего разделения JavaScript по страницам: PDF.js занимает около 1,8 МБ.

## Приоритет 2 — заметно улучшит пользовательский опыт

1. **Добавить skeleton-экраны и состояния загрузки.**
   - Каталог, заявки, история заявки, обращения в поддержку, предпросмотр документов.

2. **Оптимистично обновлять интерфейс.**
   - Подходит для корзины, количества позиций, отметок и операционных статусов.
   - При ошибке сервера нужно откатывать изменение и показать понятное сообщение.
   - Создание брони и выдачу оборудования подтверждать только после ответа сервера.

3. **Добавить трассировку и мониторинг.**
   - OpenTelemetry: длительность HTTP-запросов, SQL-запросов, расчёта availability и генерации документов.
   - RUM/Sentry: реальные ошибки и скорость интерфейса на устройствах пользователей.

4. **Тестировать на слабых устройствах и сетях.**
   - Проверить Mini App на медленной сети и ограниченном CPU мобильного устройства.

5. **Настроить пул подключений PostgreSQL явно.**
   - Зафиксировать допустимые `pool_size`, `max_overflow`, `pool_timeout` под фактическую нагрузку.

## Уже реализовано полностью или частично

- Изображения каталога уже обрабатываются и хранятся как **WebP**.
- Есть основа защиты от дублей бронирования через `client_request_id`.
- Автодополнение адреса и поиск профиля уже используют debounce 350 мс; запросы подсказок отменяются при новом вводе.
- Независимые стартовые запросы Mini App уже выполняются параллельно через `Promise.all`.
- Клиентские API-вызовы имеют таймаут примерно 20 секунд.
- SQLAlchemy использует пул соединений по умолчанию.
- Обновление доступности использует SSE вместо постоянного polling.

## Пока не приоритетно

| Идея | Почему не сейчас |
| --- | --- |
| AVIF | WebP уже даёт основную выгоду; AVIF усложнит обработку изображений. |
| CDN для статики | Имеет смысл при заметном внешнем трафике или удалённости пользователей от сервера. |
| Несколько инстансов и балансировщик | Нужны после подтверждённого роста нагрузки; потребуется общий Redis и адаптация SSE. |
| SSR / SSG | Почти не относится к персонализированной Telegram Mini App. |
| Потоковая выдача AI-токенов | В приложении нет пользовательского AI-чата. |
| Отложенная загрузка Telegram WebApp SDK | SDK критичен для Mini App, откладывать его рискованно. |
| Self-host шрифтов | Актуально только если есть существенные внешние шрифты; сейчас это не узкое место. |

## Инфраструктурная проверка

Приложение и PostgreSQL должны находиться в одной сети или регионе. Это базовое требование для стабильной задержки, но не отдельная первоочередная оптимизация.

## Рекомендуемый порядок работ

1. Измерить `/api/miniapp/availability`, устранить N+1 и добавить индексы.
2. Включить кэширование статики и Brotli/Gzip.
3. Лениво загружать PDF.js, добавить skeleton-состояния.
4. Внедрить пагинацию API.
5. Добавить Redis и очередь фоновых задач.
6. Подключить OpenTelemetry и RUM.
